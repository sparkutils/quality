114   /**
115    * Creates a ProcessFactory[I,O], when forceMutable || !compile is true it uses chained MutableProjections,
116    * otherwise, and by default, GenerateDecoderOpEncoderProjection.
117    *
118    * GenerateDecoderOpEncoderProjection is likely far faster on larger rules or higher number of threads for throughput.
119    * Unlike Spark compilation caching, which evaluates codegen for an expression tree every time, the codegen takes place
120    * once, each instance call simply returns a new class instance with fresh state for a thread.  If using forceVarCompilation,
121    * once the number of input fields goes beyond [[maxVarCompilationInputFields]] the code will fallback to INPUT_ROW based processing.
122    *
123    * The chained MutableProjections generate new class code for each instance.  They will also recreate the entire
124    * expression tree if a stateful expression is identified when compile = false
125    *
126    * The caller is responsible for ensuring the [[O]] output encoder can be applied to the resulting 'DataFrame'.
127    *
128    * @param dataFrameFunction
129    * @param compile when false reverts to interpreted mode, when true and forceMutable is true it is recommended to cache the instances
130    * @param forceMutable when true it forces MutableProjection's to be used, compiled or otherwise, the default of false is likely far faster
131    * @param forceVarCompilation defaulting to false it will, when compile is true and forceMutable is false, use variables rather than INPUT_ROW to generate code.
132    *                            Although using true is faster past 10 fields, the compilation approach (as of 0.1.3.1) is experimental
133    *                            and only supported on version OSS 3.2.1 and above
134    * @tparam I
135    * @tparam O
136    * @return
137    */
