121    * GenerateDecoderOpEncoderProjection is likely far faster on larger rules or higher number of threads for throughput.
122    * Unlike Spark compilation caching, which evaluates codegen for an expression tree every time, the codegen takes place
123    * once, each instance call simply returns a new class instance with fresh state for a thread.  If using forceVarCompilation,
124    * once the number of input fields goes beyond [[maxVarCompilationInputFields]] the code will fallback to INPUT_ROW based processing.

128    *

130    *
